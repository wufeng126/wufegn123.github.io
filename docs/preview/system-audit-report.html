一、先看结论（三句话）

1. 系统能跑，明细能信，汇总不能直接汇报。单条工资、单张结算单、单笔付款的字段和计算都是自洽的；但"利润、回款率、供应商应付"这三个对外数字，在不同页面有三套算法，同一个项目能算出三个结果。

2. 最危险的不是算错，而是"悄悄算错还看不出来"。数据超过一千条时，首页看板、项目详情、签证、生活费等多处统计会静默少算，不报错、不提示。

3. 界面像几个时期拼起来的。业务骨架完整、口径做得很细，但入口重复、移动端信息密度过重，属于"熟人带一次能用、新人自己摸会卡"的水平。

必须先修的一条（我们自己上一轮改动引入）：月报填写页选好审批人后点"提交"，系统会报"请选择项目经理作为下一级审批人"，提交必失败、钉钉也不会通知到人。

二、会算错钱、会卡流程的 11 条（建议立刻修）

最高1. 反审核班组结算，会把已经发出去的工资删掉
现在
班组结算审批通过后会生成工人应发工资。之后点"反审核"，系统会删掉这批工资——连已经付过钱、有银行流水的发放记录一起删。
会导致什么
钱明明付了，系统里变成"没付"，现金流凭空变好；事后无法还原，只剩一行后台日志。
怎么改
反审核前先检查有没有发放记录，付过钱就禁止反审核。
改完效果
已经发生的付款，任何审批动作都抹不掉，能和银行流水对上。
最高2. 月报"已回款"把退票、作废、没审核的钱也算进去了
现在
月报取甲方付款时没有筛状态，直接求和；而首页看板、成本利润中心都会先筛"有效付款"。
会导致什么
收错的、重复录的、退票作废的钱都被当成"已到账"，回款率虚高、应收未收被低估，按这个数排资金计划会踩坑。
怎么改
月报也按"有效付款"筛选，和首页同源。
改完效果
月报、首页、成本中心三处回款数字一致。
最高3. 月报"累计人工成本"只算了本月班组结算
现在
累计成本里的班组结算取的是"当月区间"，却拼进了"累计"总额。
会导致什么
历史月份的班组结算在累计里凭空消失，累计人工成本偏低、累计利润偏高；和成本利润中心对不上，差额正好是历史班组结算总额。
怎么改
累计和本月分开取数。
改完效果
月报累计利润 = 成本中心累计利润。
最高4. 同一笔供应商结算，三个页面算出三个数
现在
老系统迁过来的结算数据，在"月报""成本利润中心""供应商台账"三处各用了一套去重方法，其中成本中心那套会把真实的旧数据误判成重复丢掉。
会导致什么
月报偏高（重复算）、成本中心偏低（有的项目整块算 0）、台账折中。同一个项目永远对不上，且查不出原因。
怎么改
三处统一用同一套合并规则。
改完效果
供应商结算成本三页一致，老数据不重不漏。
最高5. 班组结算的"成本"和"应发"是两套算法
现在
成本按分项合计（不减借支、劳保、帮工、安全基金四项扣款）；应发是扣完这四项的。
会导致什么
同一张结算单，"班组成本"比"班组应发"多一个扣款额。老板问"这个班组到底花了多少"会得到两个数。
怎么改
台账并列显示"分项合计 / 四项扣款 / 应发"三行，成本口径固定为分项合计。
改完效果
差额一眼能看出来，正好等于四项扣款。
最高6. 同一工人同月"手工工资 + 班组分账"被算两次成本
现在
审批通过时如果发现这工人本月已有工资，系统悄悄跳过不生成分账工资，只写一行后台日志；但成本侧仍按整张结算单全额计入。
会导致什么
人工成本虚高、利润偏低；工人台账里看不到这笔分账应发，工人来对账对不上。
怎么改
审批前拦住并提示"这几人本月已有工资"，让审批人二选一。
改完效果
一人一月只记一次成本，台账能对上。
高7. 产值有三种算法，利润率会出两个数
现在
月报按"结算额"、成本中心按"开票额"、税费又按开票额算。
会导致什么
报量 100 万只开票 60 万的月份，一个页面利润率 8%、另一个 25%，老板没法判断到底赚没赚。
怎么改
全站定一个收入口径（建议结算额），开票额单独显示为"未开票额"。
改完效果
利润率全站一个数。
高8. "本月实发"在月报和工资页不一样
现在
有的发放记录没填"哪个月的工资"，月报按付款日期算进去了，工资页却当无效记录不算；一人多项目时同一笔钱还可能算两遍。
会导致什么
月报实发偏高、工资页"已发"偏低，按哪页发钱都可能错。
怎么改
统一按"工人 + 项目 + 月份"匹配，发放时强制填月份。
改完效果
两页实发相等，跨项目不串账。
高9. 月报提交时选了审批人，但提交会失败
现在
填写页把"分析内容"和"审批人"分两次发送，真正提交的那次没带上审批人，后台报"请选择项目经理作为下一级审批人"。
会导致什么
预算员反复选人、反复失败，流程永远卡在第一步，钉钉也不会通知到人。
怎么改
提交时一次性带上审批人（小改动）。
改完效果
一次提交成功，被选中的审批人马上收到钉钉待办。
高10. 待我审批点进去，批不了
现在
从"待我审批"点"去审批"，进的是结算单详情页，而详情页没有"通过/驳回"按钮（按钮只在台账列表行内）；详情页自己也能"提交审批"，但不选审批人、也不显示谁审批。
会导致什么
老板顺着钉钉通知点进来，翻到底也找不到"通过"，只能退回台账一个个找。
怎么改
详情页补齐"通过/驳回"，所有提交入口统一走同一个选人弹窗，并显示"下一审批人：某某"。
改完效果
点进来就能批完，谁批、批到哪一步一目了然。
高11. 从链接点进月报，永远显示"本月"
现在
月报页面不读链接里的月份和项目参数，永远显示当前月和"全部项目"。
会导致什么
点 9 月的"查看月报"，打开的是 10 月；审批完回来核对，看到的不是刚处理的那张。
怎么改
进页面先读链接里的月份、项目，页头写清"正在看 2026-09 · 某某项目"。
改完效果
点哪个月看哪个月，审批完能马上核对。

三、会影响系统长期运行的问题（工程层面）

问题会导致什么怎么改
数据超过一千条就悄悄少算（首页看板、项目详情工资、签证、生活费等多处）不报错、不提示，数字直接偏小；项目详情里工资能少一半，KPI 和明细对不上改成分批取全量再统计，或让数据库直接汇总
删一条工资发放记录，系统会把所有发放记录重算一遍并逐条写库数据一多就超时、改一半报失败，用户反复点会重复发放；写失败被吞掉，工资长期标成"未发"只重算受影响的那几个人，批量一次写完
有问题的手工点"执行迁移"仍会重放删除脚本；没有数据时还显示"成功"点一次可能删掉知识库文档、合并工人，不可逆；失败时还以为成功改成只跑新增部分，执行前二次确认
4 个接口没有登录校验（投标估价、内部单价、内部附加结算等）未登录就能拉走商业机密，登录用户也能看非授权项目金额加登录校验 + 项目范围校验

综合费用、供应商结算、零星材料之间没有互斥校验同一笔机械租赁可以在两处各录一次，成本翻倍录入时检测"疑似重复"并提示

五、操作体验：卡在哪

卡点用户会怎样建议
"我的提交 / 待我审批"藏在 工作台 → 我的提交，手机要三步老板根本找不到待审批，只能等人打电话手机底部导航给"待我审批"一个带数字角标的位置
顶部"待处理 N 项"统计的是"我提交、等别人处理"的，不是等我审批的老板看到"0 项"以为没事，其实有一堆等他批两个数字分开显示
待审批接口失败时被静默吞掉，只显示"暂无待你审批"网络一差就永远显示"暂无"，他就不再来看了失败时红字提示 + 重试按钮
手机上班组结算默认是 17 列的宽表，要左右拖，且没有"可滑动"提示只看到项目名和金额，以为没有"已付/未付"手机默认进卡片视图，宽表加右侧渐隐提示
顶部 8 张统计卡竖排，要滑很久才看到单据；草稿/待审批/已通过/已驳回全是同一个蓝色标签打开先滑过 8 张卡；分不清哪张等他批手机只留 4 张关键卡；状态用灰/橙/绿/红
长表单误触返回就全丢，没有"有未保存内容"提醒在工地录半小时，一滑返回全没了离开前确认 + 自动存本地草稿
月报页数据还没加载完就能编辑，加载完把你打的字覆盖白打一段加载完才允许编辑
编辑结算单时能改项目/班组，但保存不生效以为改对了，其实单子还挂在老项目上要么锁死这两个字段，要么真正保存
台账行内点"通过/删除"，提示在屏幕最上方（看不到），按钮还能连点；确认框是浏览器原生弹窗以为成功了再点一次，导致重复审批就地弹提示（成功绿/失败红）、按钮转圈禁用
金额框把"1,000""1000元"悄悄当 0；扣款超过结算金额，实付直接变 0 没提示；付款比例打不进小数算出来是错的还不知道；扣多了只看到 0输入即校验 + 红字提示 + 允许小数
批量导入"选中文件就写库"，说明让填英文代码但模板是中文选错文件只能一条条删；照模板填又被判格式错先预览"将导入 N 条、重复 M 条"，确认后再入库
空列表只有"暂无数据"，没有下一步按钮新人打开一片空白，不知道先建项目还是先导花名册每个空状态给一句"下一步做什么" + 主按钮

六、界面观感：为什么觉得"不好看"

不是配色丑，是像几个时期拼起来的。具体表现：

不统一的地方具体表现
圆角同时有 4 / 8 / 10 / 14 四种圆角
卡片有的带阴影、有的没有

七、做得好的地方（客观说）

  • 单条明细可靠：一条工资、一张结算单、一笔付款，字段和计算都是自洽的
  • 删工人的保护：已经堵住了"删工人连带删一堆数据"的坑
  • 月报填写页：系统数据只读、只填分析，这个设计方向是对的
  • 成本口径的细节：扣款、付款比例、尾款都分了，只是各处算法没统一
  • 权限粒度：项目级预算员/项目经理、审批人指定，方向正确

八、建议的修复顺序

第一档：立刻修（会算错钱 / 会卡流程）　约 1~2 天

  1. 月报提交丢失审批人（我们自己引入的，最先修）
  2. 反审核删掉已发工资
  3. 月报"已回款"没筛作废单
  4. 月报累计人工成本漏算历史月份
  5. 待我审批详情页没有通过/驳回
  6. 月报页不认链接里的月份

第二档：这周修（口径统一 + 稳定性）　约 3~5 天

  1. 供应商结算三处合并规则统一
  2. 班组"成本 / 应发"口径统一
  3. 同一工人同月重复计成本（改成审批前拦截）
  4. 产值口径统一（以结算额为准）
  5. 本月实发匹配规则统一
  6. 超过一千条少算（首页、项目详情、签证、生活费）
  7. 删一条发放全表重算（超时 + 重复发放）

第三档：两周内（精简 + 界面）　约 1~2 周

  1. 合同 / 结算 / 用户权限 / 工资发放 入口去重
  2. 删 4 个幽灵页面、6 个假开关
  3. 手机端宽表改卡片、状态上色、统计卡减量
  4. 长表单防丢、金额输入校验、导入预览
  5. 统一五类组件和配色

九、修复前，老板先核对这 3 个数字

先核对为什么要核怎么核
累计利润（连带累计人工成本）受第 3、4、5、6 条影响，是目前最容易被高估的数把"累计人工成本"拆成"手工工资 + 各月班组结算分项合计"，看历史月份有没有漏计
本月 / 累计已回款受第 2 条影响，最容易虚高导出本月甲方付款，把作废和待审核的单据挑出来，看月报数字是否含了这些钱
供应商应付未付受第 4 条和悬空数据影响，最可能对不上账单独查"只在旧表里有结算"的项目，看成本中心是否算成 0
